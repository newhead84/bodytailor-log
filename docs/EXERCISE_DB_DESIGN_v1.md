# 운동 종목 DB 재설계안 v1 (2026-08-02)

> 범위: 이번 세션은 **설계 확정까지만**. 실제 라이브러리 데이터 구축·기존 데이터 마이그레이션은
> 별도 세션에서 진행한다(사용자 확인).
>
> 배경: 기존 `free-exercise-db`(Unlicense/퍼블릭 도메인으로 알고 사용 중이던 이미지 데이터셋)가
> 실제로는 유료 라이선스임이 확인되어, 관련 데이터·이미지를 전량 교체해야 한다.

## 1. 기초 필드 (9개, 필수)

| # | 필드명 | 타입/예시 | 설명 |
|---|---|---|---|
| 1 | 운동명 | string | 2번 네이밍 규칙을 따르는 최종 표시 이름 |
| 2 | 부위 | enum (가슴/등/어깨/이두/삼두/하체/코어/유산소) | 기존 원자 단위 부위, 변경 없음 |
| 3 | 그립형태 | enum (오버핸드/언더핸드/뉴트럴/와이드/내로우/해당없음 등) | 없는 종목은 "해당없음" |
| 4 | 세부부위 | string (예: 상부가슴/하부등/전면삼각근 등) | 부위 내 더 구체적인 타겟 지점 |
| 5 | 장비 | enum (바벨/덤벨/케이블/머신/스미스/밴드/맨몸 등) | 네이밍 규칙의 "장비명" 필수 요소와 연동 |
| 6 | 운동패턴 | enum (밀기/당기기/스쿼트/힌지/런지/회전/등척성 등) | 프로그램 밸런스 파악용 |
| 7 | 좌우분리 | boolean | true면 "원암"(팔) 표기 대상. 하체는 접두사 없이 그대로(사용자 확인) |
| 8 | 기본단위 | enum (weight+reps / reps-only / cardio) | 현재 `getExerciseInputType()`과 동일 개념, 그대로 유지 |
| 9 | 난이도 | enum (입문/중급/고급) | 표시는 옵션(추천 종목 정렬 등에 활용 가능) |

## 2. 추가 제안 필드 (선택, 2~3개만 채택 권장)

개인용 셀프 기록 앱 특성상 입력 부담을 늘리는 필드는 최소화하는 게 좋아, 아래 중 실제로
쓰임새가 있는 것만 선택 채택을 권장한다.

| 후보 | 설명 | 채택 권장도 |
|---|---|---|
| 주동근/보조근 | 이 운동이 주로/보조로 자극하는 근육 | 중 — 라이브러리 정확도에 도움, 그러나 사용자 화면 노출은 선택 |
| 가동범위(풀레인지/부분) | 풀레인지 vs 부분가동 구분 | 낮음 — 실사용 빈도 낮을 수 있음 |
| 복합관절/고립관절 | compound vs isolation | 중 — 향후 "과부하 추적"·루틴 밸런스 분석에 유용 |
| 안전주의사항 | 부상 위험 주의문구 | 선택 — 있으면 좋지만 필수 아님 |
| 대체운동 | 부상/장비없음 시 대체 종목 ID | 선택 — 향후 "대체 종목 추천" 기능과 연동 가능 |

**권장안**: 필수 9개 + 선택 2개(복합관절/고립관절, 주동근) 정도로 시작하고, 실사용 피드백에
따라 늘려가는 방식을 제안.

## 3. 운동명 네이밍 규칙

```
[각도/그립 (선택)] + [장비명 (필수)] + [운동 기본 명칭 (필수)]
```

**예시**
- 인클라인 + 바벨 + 벤치프레스 → **인클라인 바벨 벤치프레스**
- 리버스그립 + 케이블 + 랫풀다운 → **리버스그립 케이블 랫풀다운**

**조건 1 — 관용적으로 장비명이 생략되는 운동**
펙덱플라이처럼 원래부터 "머신"을 붙이지 않아도 일반적으로 머신 운동으로 통용되는 이름은
억지로 장비명을 붙이지 않는다 (예: "머신 펙덱플라이"가 아니라 "펙덱플라이" 그대로).

**조건 2 — "원암" 접두사 (좌우분리 표기)**
한쪽씩 번갈아 하는 상체/팔 운동에 한해 "원암"을 붙인다 (예: 원암 덤벨로우, 원암 케이블컬).

- **하체 운동은 접두사를 붙이지 않는다** (사용자 확인, 2026-08-02). 한다리씩 하는 하체
  운동(불가리안 스플릿 스쿼트, 워킹런지/스테이셔너리런지, 원레그 데드리프트(RDL), 스텝업,
  피스톨 스쿼트, 원레그 카프레이즈 등)은 그 자체 명칭을 그대로 사용하고 별도 접두사를
  추가하지 않는다.

## 4. 마이그레이션 시 확인할 것 (다음 세션 착수 전 체크리스트)

- `free-exercise-db` 의존 파일 전량 삭제 대상: `utils/exerciseImageMap.js`,
  `utils/exerciseImageApi.js`, `components/ExerciseGuideImage.jsx` (이미지 소스 자체 교체 필요)
- `utils/exerciseLibrary.js`의 `EXERCISE_LIBRARY` 데이터 전체를 위 네이밍 규칙에 맞게 재구축
- 기존 저장된 사용자 기록(`workoutLogs`)에 남아있는 옛 종목명과 새 이름이 다를 경우, 이름
  매핑 테이블(옛이름 → 새이름)이 필요할 수 있음 — 사용자의 과거 기록 표시가 깨지지 않도록
  마이그레이션 스크립트 또는 표시 단계 폴백 매핑 필요
- `favoriteExercises`(내 루틴 flat 리스트)에도 옛 종목명이 저장되어 있으므로 동일하게 이름
  마이그레이션 대상
- 새 이미지 소스(퍼블릭 도메인 확인된 것으로) 선정 필요 — 라이선스 재확인 필수
